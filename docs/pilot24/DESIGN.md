# Pilot24：六题离线设计与冻结要求

状态：`DESIGN_READY_FOR_MATERIALS`。本文件是可实施设计，不是已验证的材料冻结或可执行批准。2026-10-11 13:29:22 UTC，用户在父任务 `01a118ba-de9d-7788-9f06-6ddc22e12017` 的消息 `Sentinel_fd07ce9accfc8191af13a367c14ce6ff` 回复“可以”，批准最多24次新生成及设计推进。凭据发送仍是用户本地动作；未来新候选的精确执行许可另行落实。本设计阶段新增候选执行/模型请求均为0，72请求反馈方案不在范围。

## 1. 实验问题和样本单位

6个不同业务规格 × IR/JS两种表示 × 2次全新会话 = 最多24次生成。六题均把正确旧版v0修改为新版v1；覆盖多步修改、跨规则约束与旧行为回归，不声称覆盖从零创建或故障定位。每份代码只生成一次，零反馈、零工具、零修复。主问题是：在相同业务信息、共享宿主和预算下，哪一种表示条件更容易完成这些修改？不预设IR胜出。

任务是主要比较/聚类单位，共6个；每任务每表示2份生成，共每表示12份。独立会话指请求不携带其他答案或历史，不等于统计独立同分布；temperature=0可能产生相同代码，仍保留两条原记录。每题12个固定场景，每份代码运行12例，共计划288例，种子固定1，不使用RNG。用例、重放和同题重复生成均不能冒充新的独立任务。所有结论只能是小型探索结果。

[六题语义和72个场景设计](TASKS.md)先于任何新生成。过去Door案例与观测后新增诊断是开发材料，不进入新题主分数，也不得重新命名为holdout。新题也称“前瞻冻结的小样本任务集”，不夸称具有广泛代表性的留出集。

## 2. 复用边界与可表达性

已只读核查：`headless_v01/compiler.py`支持自定义字段/事件record、bool/int/EntityID、eq/ge/le/gt/lt、if/let、checked sub、write/emit；runtime的EntityID eq是值比较。`ark_eval/host.py`把相同宿主操作交回现有Job/Transaction。`node_worker.mjs`与`candidate_parser.mjs`要求唯一导出onOpen，但payload不固定为player/door。`pair003_ir_worker.py`编译完整Core，案例引导不固定Door字段。相关内核/网络/资源隔离保持不变。

为免扩张路由，每题均沿用Core handler `id=open,event=Open,priority=0`与JS `export function onOpen(ctx, payload)`；Open仅是历史传输名字。六题各自有不同payload record、字段、输出事件和算法，不能把入口同名理解为六道开门换皮题。JS宿主使用该题完全相同的Core声明头和空handler body；IR提交该头加原生body。只能有这一个handler，Tick:{}、services:{}、extensions:{}固定，字段/事件/范围/authority/policy不能由候选改写。只有数据与薄评测配置需要新增。

不复用已消费的v4批准或执行scope，不修改旧freeze、候选、oracle和成绩。Sol材料阶段不改`headless_v01/*`、宿主事务/IPC、安全profile、worker或现有权限系统；不能用新架构解决题目困难。将来新批次入口复用已有摘要绑定、预算审计、隔离与一次性领取机制，不再设计一套权限系统。

共同公共能力说明只提供完成任务所需的既有操作：resolve/exists、read/require、checked整数sub、write、emit；原生局部变量、条件、短路和比较。IR使用literal/var/let/record及原生控制节点；JS使用自然的guard clauses、const/let、条件和允许的纯局部helper。整数加法可表达为`sub(a, sub(0,b))`，两臂都获得此接口语义，不能只教一臂。EntityID是四元组，IR eq按值比较；JS说明四个成员逐一比较的等价方法，不得误用数组引用相等。不给新增宿主API、TS、服务、网络、文件、时间、动态导入或随机工具。必要准入一直存在，“无工具”只指模型看不到验证反馈。

## 3. 共同语义及可观察范围

- 每题的实体角色只是字段使用约定，不新增实体类型。EntityID按值识别；除M2的显式别名no-op规则外，两个角色可指同一实体，只要所需字段齐全；其不同名字的字段按同一对象更新。
- 所有声明字段authority=IR、policy=exclusive；bool无数值替代，int为safe-int且存储范围见任务表。不存在的实体按各题最外层规则正常返回。read返回option；在当前路径需要的cell上require(none)为InvalidEntity，不可默认为0/false。各题明确的短路优先级必须保持，无害的提前read不强制逐调用相同。
- payload由可信调用方符合指定类型和任务域；C2的amount在0..4，R2的steps在0..3。域外值不纳入本轮业务规格/评分，不偷偷追加为隐藏题。缺cell是允许的诊断状态；不把类型/范围非法的初始世界作为候选业务错误。
- 每个case是全新世界，seed=1；同一case可有两个输入事件或两个tick，按指定顺序处理。先前输入事件的提交效果对同tick后续输入事件可见。任一错误使整个tick ABORTED，恢复该tick开始时的状态，已发布业务事件/命令为空；先前已成功tick不回滚。
- 业务规范要求先确定当前决策所需值再发生业务效果；primary oracle比较最终实体/字段、逐tick状态、错误码、按序发布的业务事件/命令和重放。不会凭最终状态假称证明了全部内部路径或require-before-effect；需要额外动态轨迹才可声明的属性另标NOT_CHECKED。中间尝试效果日志不是已发布事件，不能混淆。
- 默认为没有其他字段变化、没有未列出的输出事件、commands=[]。所有拒绝事件也是精确业务结果；条件不符的正常拒绝属于COMMITTED。表中“无变化/无事件”是COMMITTED，只有明确标注的缺必需cell为ABORTED/InvalidEntity。更严格的错误phase、源码节点编号和无害host-call顺序不参与两臂等价评分。

## 4. 两个同等质量starter的要求

每题提供一个完整、正确、可读的v0 Core JSON与一个同语义v0 JS callback。它们使用相同v0字段头（包括新版本将用但v0忽略的字段/参数）、同一错误/终态规则与输出事件；共同说明明确哪些v0行为将被替换。不能给IR空body却给JS最终解，或给JS仅TODO而IR已完成大半。IR用具名let、清楚分支和复用局部值；JS用常量、guard clauses、清楚局部值及必要纯helper。禁止JS包装IR JSON、故意降低JS质量、额外透露一臂的最终参考实现。

每份model请求仅包含：共同任务域/宿主语义/资源限制；该题v0与v1文字需求、保留/新规则表；该表示的API语法与独立小例子；自己的v0 starter；输出格式。共用语义逐字相同；表示语法可以不同，但事实/例子信息量逐项配对。共享示例仅用独立Probe字段，不展示六题完整算法。不给对侧starter、目标v1控制、故障控制、case输入/expected、评分集合、其他回答、前轮结果或本设计的私有场景表。

Sol需独立编写：12份公共v0 starter；12份私有可信v1控制（每题IR/JS各一）；每题至少3种私有手工故障控制（漏改、跨规则错误、旧行为回归），并保持两个表示相同缺陷意图。它们均不是模型候选。先从本文契约手写oracle，再用控制去检验oracle与实现一致；不调用参考控制输出作为oracle生成器。v0在保留集合上与v1有相同可观察结果；N/B组允许按新需求与v0不同，不能据此说v0不正确。

## 5. 模型、上下文与4096输出可行性

固定已在本项目四次HTTP200审计中使用过的Plan模型标识`deepseek-v4-1-flash-260910`，端点仅`https://ark.cn-beijing.volces.com/api/plan/v3/chat/completions`。参数沿用历史已用组合：max_tokens=4096、temperature=0、stream=false、thinking={type:disabled}。历史成功不是当前额度/服务可用性的保证；本轮不联网核验、不改模型别名、不回退到普通按量路由。

每请求：1次尝试；输入估算量`sum(UTF-8(content)字节数 + 256/消息)`最多24,000单位；输出上限4,096 tokens；原始源码最多16,384 UTF-8 bytes；零修复/工具/重试。24次输出上限总计98,304 tokens。两臂使用相同语义信息和上限，实际token不同照实记录，不padding，也不截去一臂的必要内容。Plan额度不等于token预算，禁止据此承诺费用或额度够用。

这是相同输出token上限、尝试/修复上限和输入估算上限的对照；输入估算尚非模型tokenizer，不能宣称严格相同的输入或总token预算已被验证，也不宣称实际用量相同。若复审要求严格输入token上限，须先有与该版本匹配的可信离线计数及预声明上限，不能靠真实探针、事后补预算或padding补救。`input_units_are_tokens=false`、`input_token_upper_bound_claimed=false`随协议保留；此限制必须进入任何后续结果解释。

历史单份IR为37个op节点、5,066 bytes、955输出tokens；本轮尚没有实体starter或控制，**不能声称新题已通过4096适配验证**。设计估计M1/M2约40–65节点，C1/C2/R1/R2约55–100节点；它们都是单handler、有界常量/布尔/整数，不含列表循环、外部服务或宏系统，预计可以保持短程序。这个估计只用于筛选，不是分词器保证。

材料冻结前逐题满足：公共原生starter与私有目标控制均能放入源码16KiB；目标IR优先控制在100节点/10,000 bytes以内；实际组装的两消息请求经现有prepare估算均≤24,000。优先把完整IR正文的保守token估计控制在3,072以内，留输出余量。若没有与该服务版本匹配的离线分词器，报告未验证及历史比例估算，不安装/调用额外模型探测，不把byte当token。任何题有明显超限风险，先在看答案前缩小**双方同一业务规格**再复审，不能增加4096上限、发探针请求、只压缩一臂必要信息，或生成后再降难度。

控制的最长路径建议≤24个JS wire消息（含done），为已有32/handler留余量；同一tick共同host操作≤128、JS wire≤256，资源沿用10秒/调用、64MiB、0.25CPU、32 PID、无网络/个人挂载。每case最多两个输入事件/两个tick；Sol需用可信控制实测预算与引导帧≤32KiB、响应帧限额，不把IR AST步数与JS计算量视为相同单位。若不能在现有资源内表达，暂停该题而不是放宽隔离。

规划用量参考仍为24次合计60,720–242,304 tokens（每请求输入2,400–6,000、输出130–4,096的情景假设），按旧实耗机械外推82,092；均不是预算保证。当前只批准24次规模，不扩大到72。

## 6. 调度、评分与停止

完整24槽见[schedule.json](schedule.json)。第一轮M1,M2,C1,C2,R1,R2；第二轮反向任务顺序。每题第二轮的IR/JS先后次序反转，每轮各有3题IR先、3题JS先。重复请求的公共内容相同（不加入“再试一次”或前轮反馈）；rep/repetition/slot仅在审计元数据中标识。每槽全新messages、一个HTTP请求，未知响应也占已尝试槽；不去重相同代码，不挑最好的一份，最多24次。

模型生成级与用例级分别计分：

| 情形 | 生成级 | 用例级/后续动作 |
|---|---|---|
| 完整候选，12例及准入/重放/清理通过 | PASS | 12 PASS，进入下一固定槽 |
| 完整候选有正常功能、跨规则、回归或已确定的语法/声明头错误 | FAIL并分类 | 实际跑过的场景照实；语法/声明拒绝则12 NOTRUN，不能假写12个实测FAIL；不修复，按预定范围继续 |
| 身份/usage/协议均可信的HTTP200，finish_reason=length | FAIL_TRUNCATED，消耗该槽 | 原文隔离保存，不执行截断代码，12 NOTRUN；不补发；未来已审入口可按固定表继续后续槽 |
| 同样可信的正常结束却空答案 | FAIL_EMPTY，消耗该槽 | 12 NOTRUN，不修复，继续预定槽 |
| HTTP鉴权/额度/服务错误、身份/usage不可信、未知结果或传输超时 | ERROR_PROVIDER或OUTCOME_UNKNOWN，不伪作模型功能失败 | 立即停批，保留尝试与未知用量，剩余NOTRUN，不自动重试/换目录补齐 |
| 发送前材料漂移/超限/信息泄漏/歧义；执行时隔离、准入机制或清理不明 | BLOCKED/INVALID_EXPERIMENT | 停止并复核，保留所有原始记录；不得改oracle后覆盖成绩 |

“确定候选错误”与“环境/协议不明”的分类必须先有可信故障测试；不能仅因IR编译进程异常退出就猜成候选FAIL。未来入口复用现有严格导入器，对可继续的已知质量失败做显式、经mock测试的分派；身份/安全判断绝不放松。当前旧四槽发送入口仍保持原样；在新入口未复审之前，上表没有任何实际发送路径。

主分数是每份生成全部12例通过的pass-at-1；每题分别报两份结果，以六题等权汇总，并列每臂12份生成分母和任何FAIL/ERROR/NOTRUN。对于完整有效批次，令`p[t,a]=(该任务该表示两份生成的PASS数)/2`，`score[a]=sum(p[t,a])/6`，`delta=score[IR]-score[JS]`；不挑最好一份，不把pass-at-2当主分数。另列N/B/R三组场景结果、旧行为回归、语法/声明/截断、真实usage；不按源文件长短、调用轨迹或测试个数选赢家。基础设施中断未完成配对时只报告部分描述结果，不过区分度门。

冻结前成功门：v0通过自己的旧版控制集合及R01–R04；可信v1两臂全部12例及重放一致；每题3种故障控制都被至少一个预定场景检出；12份请求材料等信息、长度与预算可行；无私有材料泄漏。失败先修材料，模型调用仍为0。

24槽完整且有效时：至少两个不同规格满足`p[t,IR] != p[t,JS]`，并且`abs(delta) >= 1/6`，才值得建议新的独立确认实验；此门对IR/JS对称，只是后续投入条件，不是显著性或优势证明。两边全过、全不过、差异不足或集中在一题就记天花板/地板/证据不足，不自动扩样。题目歧义或oracle错误须显式INVALID_TASK并保留原数据；生成后观察到的新边界只能进入另一个开发版本，不追加入本轮主分数。

## 7. 冻结与交接

Sol先按[TASKS.md](TASKS.md)和[HANDOFF_SOL.md](HANDOFF_SOL.md)制作公共/私有材料与可信测试。材料通过公平性和预算复审后，才生成新的内容摘要freeze；本设计的文件哈希仅标识交接版本，不是该freeze。统一用户本地调用入口是再下一步；不改旧入口、不读取/搬运/打印密钥、不发带密钥请求。用户对24规模的“可以”不能填进旧批准文件，也不能替代未来具体源码执行范围的确认。
