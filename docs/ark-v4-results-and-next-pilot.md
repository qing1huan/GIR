**结论边界。**

- 这是 **4次生成、4份代码、2个任务变体、1个 Door 业务模板**。每份代码是13种原场景加4种诊断场景，再乘seed 1/123得到34例。运行种子与重放不增加独立生成或任务样本数；不能以136为独立样本做模型胜率或置信度推断。
- Modify 只改唯一 cost 绑定，Debug 只修反向比较。两臂都得到原生 starter、明确 ABI 和同一业务信息；结果支持“该模型在这些明确、局部的改动上完成了任务”，尚未区分复杂工程能力。
- v4 在此前观测后澄清了 missing-cell、必需值验证时机及整 tick 回滚语义；新增8例从澄清契约独立编写，并在本轮生成前冻结。这是有价值的开发闭环，**不是未见过的 holdout**。历史 JS 静态 FAIL 的措辞歧义也不能追溯改成已证实的旧任务缺陷。[v4 澄清说明](ark-door-v4-review.md)
- 完整源路径、player/door 别名、完整效果授权等仍为 `NOT_CHECKED_FULL_RULES`。测试通过不等于证明整个契约；共享宿主提供的回滚、限制和重放能力也不能全归功于模型或 IR。此前 **319项可信工程/mock 回归**与这里的模型实测分别报告。

**建议路线：先做6个不同规格 × 2次独立会话生成 × 2种表示，共24次初始生成。**

先离线准备和冻结任务、双臂原生基线、独立 oracle及预算，再另行确认这24次生成和新隔离执行范围。保持现有 runtime、宿主操作、事务语义和隔离架构；第一轮不提供模型工具反馈、不修复、不追加生成。目标是检查当前100%是否只是单点修改的天花板，并寻找可重复、方向不限的差异。

下列是候选规格，不是已经存在的测试或现成可执行入口。每个规格须包含2—3处关联改动，公共 starter为正确的旧版行为；最终目标实现保密。

| 难点 | 候选业务规格 | 主要区分点 |
|---|---|---|
| 多步改动 M1 | 多资源商店购买 | 同时验证并扣两种资源、更新商品状态、只发布一次凭据；任一条件失败不留下部分效果 |
| 多步改动 M2 | 装备替换 | 验证旧/新装备后联动更新；缺实体、旧新别名、重复请求规则预先写清 |
| 跨规则 C1 | 任务领奖 | completed、claimed、必需奖励数据的优先关系；已领奖路径不能因无关缺字段意外失败 |
| 跨规则 C2 | 护盾与伤害结算 | 免疫、护盾先消耗、剩余伤害、生命下界组合；只用现有 checked 运算和字段写入 |
| 回归风险 R1 | 资源预留新增取消路径 | 取消只归还已预留额度，重复取消不重复归还；保持原预留成功和拒绝行为 |
| 回归风险 R2 | 生产倒计时新增暂停规则 | 暂停、计数耗尽、完成事件恰好一次与终态重入；保持未暂停时的旧行为 |

独立性审查必须排除纯改名、改常数或同一算法的换皮题；不合格规格在生成前替换。六个任务仍是人为选取的小样本，不假定为六个独立同分布的业务总体样本。每个任务两次全新会话不得互看答案；温度0下可能生成相同代码，照实保留，它不是两个新增任务。先做一次小样本探索，不据此宣布普遍优势。

每个规格建议固定 **12个场景**：4个新功能、4个跨规则边界、4个未受改动影响的旧行为。预先标记哪些旧预期因需求合法改变，不能把它们混入“应保持不变”的回归指标。最小方案只用一个固定运行种子；这些任务若不用 RNG，不靠复制种子扩大样本。24份代码对应288次场景执行，另计既定重放；测试数量不是模型样本量。当前 Door 旧例、新诊断只保留为开发回归材料，不能改名成为新 holdout。

**合理对照与贡献归因。**

| 条件 | IR 臂 | JS 臂 | 可回答的问题 |
|---|---|---|---|
| 推荐的24次初始生成 | 原生 Core JSON；明确类型/schema；结构清楚的原生旧版 starter | 原生 JS callback；guard clauses、命名常量/局部变量、明确 ctx/option说明；接口允许时可用纯局部 helper | 同模型、同业务信息、同预算、无模型反馈条件下，两种表示条件的表现差异 |
| 暂不做的反馈扩展 | 同一初稿分别进入自检/验证反馈分支 | 同样分支、同样反馈语义和预算 | 等额额外生成下，验证反馈的增益及其与表示的交互 |

JS不能被迫写 `defineGame(IR_JSON)` 包装，也不能故意不给正常示例；IR不能独享最终参考解、额外约束提示或自动修复。双方各看自己的等价 starter、同一业务契约、同一组公开独立接口示例；目标参考实现与固定评分数据不发给模型。共享 runtime、oracle、外部宿主操作预算和安全限制；不强求源代码形状、内部 AST/JS 指令或安全 host-call轨迹相同。IR编译准入与JS解析/宿主准入是必要机制，照实记录拒绝阶段，不能关闭安全检查来造“无工具”组。

第一轮的“无工具”是**无模型可见验证反馈**，不是没有编译器、测试或隔离。该比较仍包含语法、文档长度、模型熟悉度和必要准入的组合效应；不能声称单独识别了“纯 IR 语法”的因果贡献。当前也没有可靠复现的旧 Vitric 基线；新的 JS最佳实践臂不得冒称 Vitric复现。TS、自动优化器和新宿主 API均不在最小方案内。

若以后确需测验证工具贡献，对24份初稿各开两个互不相见的修订分支：T0只有同一份自检要求，T1另外收到预先固定的公开诊断；每分支同样只允许一次修订、同样输出/上下文/时间上限。总计 **24次初稿＋48次修订＝72次请求**，不是在24次基础上再无条件增加72次。T0与T1共同保留必要安全准入，T1的IR/JS诊断必须提供等价事实、反馈长度和固定调用次数，不泄漏封存评分集。这样比较T1−T0才不把多一次生成误当工具增益；再比较两种表示下的增益。两个分支共享初稿，统计时须配对，不能当48个独立任务。该反馈基线尚不存在，本轮不实现，也不默认进入。

**预先冻结的成功标准和停止条件（提议，须在任何新生成前落实）。**

1. **基线有效性门。** 双臂可信旧版控制通过未改变的旧行为测试；私有目标控制通过全部目标测试。每题至少三个手工故障控制，分别覆盖漏改步骤、破坏跨规则约束、旧行为回归，每个必须被对应固定测试检出。oracle先从文字契约编写，不能从候选/参考执行输出反推；控制失败先修评测设计，不调用模型。这里的控制通过仍是工程验证。
2. **冻结内容。** 六个规格、任务家族、测试/预期、公开信息、双方 starter、模型标识/参数、两次会话安排和交替顺序、预算、评分、基础镜像/执行器摘要一次冻结。公共数据和私有评分材料分离。产生任何模型结果后发现的新边界记作后续开发诊断，不加入本轮主分数；新版本需新冻结与新样本。
3. **主指标。** 每份代码一次生成后，全部12例通过且准入/回放/清理有效，才算任务全通过。报告每臂12份生成、每题2次结果，按六个任务等权；另列旧行为回归率、跨规则失败、语法/准入/预算失败、tokens、失败与NOTRUN。运行seed和重放不作独立样本，不报用例级显著性。正常模型错误算FAIL；基础设施/协议问题保留为BLOCKED/NOTRUN，不能从分母静默删除。
4. **小试的区分度门。** 有效性门通过、无预算或信息失配、任务均有完整配对结果后，若至少两个不同规格出现表示间差异，且六任务等权全通过率的绝对差至少1/6，才值得提议更大、独立的新任务确认。这是对IR和JS完全对称的后续投入门槛，**不是统计显著性或优势结论**。两边均全过/全不过、差异只在一个规格或门槛未达，则报告天花板/地板/证据不足；不自动扩样到出现IR胜出。
5. **硬停止。** 单会话一次生成，修复0、模型工具0、自动重试0；全轮最多24次请求。模型/版本不符、额度不足、路由或响应未知、冻结摘要漂移、泄漏评分材料、契约歧义、隔离/清理失败都停止并保留记录；不补跑、不删除领取记录、不按结果改oracle。单份正常语法/功能失败如实记录，继续预定范围。若题目无效，显式标INVALID_TASK并保留双臂原始结果，不能重写后替换旧分数。
